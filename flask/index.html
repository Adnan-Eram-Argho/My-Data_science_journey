01

Flask Basics & Routing

ফ্লাস্ক (Flask) হলো পাইথনের একটি শক্তিশালী অথচ অত্যন্ত হালকা WSGI মাইক্রো ওয়েব ফ্রেমওয়ার্ক। এটি ওয়েব সার্ভারের সাথে সহজে যোগাযোগ স্থাপন করে এবং ইউআরএল (URL) রাউটিংয়ের মাধ্যমে বিভিন্ন পেজ বা অ্যান্ডপয়েন্ট নিয়ন্ত্রণ করতে সাহায্য করে।

অ্যাপ্লিকেশন ইনিশিয়ালাইজেশন ও রাউটিং

ফ্লাস্ক ব্যবহারের প্রথম পদক্ষেপ হলো Flask ক্লাস ইমপোর্ট করে মূল অ্যাপ্লিকেশনের একটি ইনস্ট্যান্স তৈরি করা। এখানে __name__ আর্গুমেন্ট হিসেবে পাস করা হয়, যা পাইথনকে জানিয়ে দেয় বর্তমান মডিউলটি কোথায় অবস্থিত — ফলে ফ্লাস্ক স্বয়ংক্রিয়ভাবে টেমপ্লেট এবং স্ট্যাটিক ফাইলগুলোর সঠিক পাথ খুঁজে নিতে পারে।

In [1] 
from flask import Flask

# ফ্লাস্ক WSGI অ্যাপ্লিকেশনের অবজেক্ট তৈরি করা হলো
app = Flask(__name__)

# রুট পাথ বা হোম পেজের জন্য রাউট ডেকোরেটর
@app.route("/")
def welcome():
    # ব্রাউজারে সাধারণ টেক্সট বা HTML রিটার্ন করা হচ্ছে
    return "Welcome to my website hi ARGHO"

# /argho অ্যান্ডপয়েন্টের জন্য আরেকটি ভিউ ফাংশন
@app.route("/argho")
def welcome_argho():
    return "Argho onk valo"

if __name__ == "__main__":
    # ডেভেলপমেন্ট সার্ভার চালু করা হলো
    app.run(debug=True)

NOTE · WSGI কী?

WSGI (Web Server Gateway Interface) হলো পাইথন ওয়েব অ্যাপ্লিকেশনের একটি স্ট্যান্ডার্ড স্পেসিফিকেশন। এটি ওয়েব সার্ভার (যেমন Gunicorn, Nginx বা ফ্লাস্কের লোকাল বিল্ট-ইন সার্ভার) এবং তোমার লেখা পাইথন অ্যাপ্লিকেশনের মধ্যে একটি সেতুবন্ধন হিসেবে কাজ করে, যাতে সার্ভার রিকোয়েস্ট গ্রহণ করে সঠিক পাইথন কোডে পাঠাতে পারে।

@app.route ডেকোরেটর ও ভিউ ফাংশন

@app.route() ডেকোরেটরের কাজ হলো একটি সুনির্দিষ্ট URL পাথের সাথে পাইথনের একটি ফাংশনকে (যাকে View Function বলে) বেঁধে দেওয়া। যখনই ব্যবহারকারী ব্রাউজারে সেই URL ভিজিট করেন, ফ্লাস্ক সংশ্লিষ্ট ফাংশনটি চালায় এবং তার রিটার্ন ভ্যালু ব্যবহারকারীর ব্রাউজারে রেসপন্স হিসেবে পাঠিয়ে দেয়।

WARN · debug=True ব্যবহারের সতর্কতা

লোকাল ডেভেলপমেন্টের সময় app.run(debug=True) রাখা অত্যন্ত কার্যকর — কারণ কোডে কোনো পরিবর্তন করলে সার্ভার নিজে থেকেই রিস্টার্ট হয় (auto-reload) এবং এরর হলে ব্রাউজারেই চমৎকার ইন্টারেক্টিভ ডিবাগার দেখায়। তবে লাইভ বা প্রোডাকশন সার্ভারে কখনোই ডিবাগ মোড অন রাখা যাবে না। ডিবাগ মোড অন থাকলে বহিরাগত যে কেউ ব্রাউজার কনসোল থেকে সার্ভারে ক্ষতিকর পাইথন কোড এক্সিকিউট করে ফেলতে পারে।

02

Templates & render_template()

পাইথন স্ক্রিপ্টের ভেতরে সরাসরি বড় বড় এইচটিটিপি স্ট্রিং লেখা পরিচ্ছন্ন সমাধান নয়। ফ্লাস্কে ডেটা ও প্রেজেন্টেশন লেয়ার আলাদা রাখতে Jinja2 টেমপ্লেট ইঞ্জিন এবং render_template() ফাংশন ব্যবহার করা হয়।

ফ্লাস্কের আবশ্যকীয় ফোল্ডার স্ট্রাকচার

ফ্লাস্ক নিজে থেকেই প্রজেক্টের নির্দিষ্ট কিছু ফোল্ডারের নাম চিনে নেয়। ওয়েব পেজের সমস্ত HTML ফাইল অবশ্যই templates নামের ফোল্ডারের ভেতরে রাখতে হয়। একইভাবে স্টাইলশিট (CSS), স্ক্রিপ্ট (JavaScript) এবং ইমেজ ফাইল রাখতে হয় static ফোল্ডারের ভেতরে।

Tree 
# ফ্লাস্ক ওয়েব প্রজেক্টের মানসম্মত ডিরেক্টরি কাঠামো:

│
└── static/                  # স্ট্যাটিক অ্যাসেট রাখার ফোল্ডার
    ├── css/

    └── js/

TIP · templates ফোল্ডারের নামকরণ

ফোল্ডারের নাম অক্ষরে অক্ষরে templates (সবগুলো ছোট হাতের অক্ষর) হতে হবে। ফ্লাস্কের render_template() ফাংশন ডিফল্টভাবে অ্যাপ রুট ডিরেক্টরির ঠিক এই ফোল্ডারেই ফাইল অনুসন্ধান করে। অন্য কোনো নাম দিলে ফ্লাস্ক TemplateNotFound এরর দেখাবে।

ইনলাইন HTML বনাম render_template()

ছোটখাটো পরীক্ষার জন্য ভিউ ফাংশন থেকে সরাসরি <html><h1>...</h1></html> রিটার্ন করা সম্ভব হলেও, বাস্তব অ্যাপ্লিকেশনে আমরা পৃথক ফাইল রেন্ডার করি।

In [2] 
from flask import Flask, render_template

app = Flask(__name__)

@app.route("/")
def welcome():
    # পাইথন স্ট্রিং হিসেবে সরাসরি ইনলাইন HTML রিটার্ন
    return "<html><h1>HI there</h1></html>"

@app.route("/argho")
def welcome_argho():
    # templates/ ফোল্ডার থেকে index.html ফাইলটি রেন্ডার করবে
    return render_template("index.html")

@app.route("/about")
def about():
    # templates/about.html ফাইলটি লোড করে ব্রাউজারে পাঠাবে
    return render_template("about.html")

if __name__ == "__main__":
    app.run(debug=True)

NOTE · Content-Type হেডার

যখন তুমি render_template("index.html") রিটার্ন করো, ফ্লাস্ক নিজে থেকেই রেসপন্সের হেডার হিসেবে Content-Type: text/html; charset=utf-8 সেট করে দেয়। ফলে ব্রাউজার বুঝতে পারে এটি একটি ওয়েব পেজ এবং সঠিকভাবে স্টাইল ও ট্যাগসমূহ প্রদর্শন করে।

03

GET & POST Requests / HTML Forms

ওয়েব অ্যাপ্লিকেশনে ক্লায়েন্ট (ব্রাউজার) ও সার্ভারের মধ্যে যোগাযোগের মূল মাধ্যম হলো HTTP রিকোয়েস্ট মেথড। ব্রাউজারের ফর্ম থেকে ডেটা সাবমিট করা এবং ফ্লাস্ক ব্যাকএন্ডে তা রিসিভ করার প্রক্রিয়া নিচে তুলে ধরা হলো।

HTTP মেথড: GET বনাম POST

GET ডেটা আনতে ব্যবহৃত হয়, প্যারামিটার URL-এ দৃশ্যমান থাকে POST ডেটা সার্ভারে পাঠাতে ব্যবহৃত হয়, পে-লোড রিকোয়েস্ট বডিতে লুকায়িত থাকে methods=['GET', 'POST'] রাউটে অনুমোদিত মেথডের তালিকা নির্দিষ্ট করে request.form['key'] সাবমিট করা ফর্ম ফিল্ডের মান উদ্ধার করে

ডিফল্টভাবে ফ্লাস্কের যেকোনো রাউট কেবল GET রিকোয়েস্ট গ্রহণ করে। কোনো রাউটে ফর্ম সাবমিশন বা ডেটা গ্রহণ করতে হলে methods=['GET', 'POST'] সুস্পষ্টভাবে বলে দিতে হয়।

In [3] 
from flask import Flask, render_template, request

app = Flask(__name__)

@app.route("/")
def welcome():
    return "<html><h1>HI there</h1></html>"

# শুধুমাত্র GET মেথড সমর্থনকারী রাউট
@app.route("/argho", methods=['GET'])
def welcome_argho():
    return render_template("index.html")

@app.route("/about")
def about():
    return render_template("about.html")

# GET ও POST উভয় মেথড গ্রহণকারী রাউট
@app.route("/form", methods=['GET', 'POST'])
def form():
    # ব্যবহারকারী ফর্ম সাবমিট করলে POST রিকোয়েস্ট আসবে
    if request.method == 'POST':
        name = request.form['name']
        return f"<h1>HI {name}</h1>"
    # সাধারণ ভিজিটে (GET) ফর্ম পেজটি দেখানো হবে
    return render_template("form.html")

# ফর্ম অ্যাকশন পাঠানোর জন্য আলাদা ডেডিকেটেড এন্ডপয়েন্ট
@app.route("/submit", methods=['GET', 'POST'])
def submit():
    if request.method == 'POST':
        name = request.form['name']
        return f"<h1>HI {name}</h1>"
    return render_template("form.html")

if __name__ == "__main__":
    app.run(debug=True)

HTML ফর্ম ও ফ্লাস্কের সংযোগ

এইচটিএমএল ফর্মে method="POST" এবং action="/form" দিতে হয়। সবচেয়ে গুরুত্বপূর্ণ বিষয় হলো ইনপুট ফিল্ডের name অ্যাট্রিবিউট। পাইথনের request.form['name'] মূলত সেই ফিল্ডের ভ্যালুটি সংগ্রহ করে।

HTML 
<!-- templates/form.html -->
<form action="/form" method="POST">
    <label for="username">আপনার নাম লিখুন:</label>
    <input type="text" id="username" name="name" placeholder="এখানে নাম লিখুন..." required>
    <button type="submit">সাবমিট করুন</button>
</form>
WARN · request.form['key'] বনাম request.form.get('key')

ফর্মে যদি name="name" ফিল্ডটি না থাকে বা ব্যবহারকারী কোনো কারণে সেটি না পাঠিয়ে রিকোয়েস্ট পাঠায়, তবে সরাসরি request.form['name'] ব্যবহার করলে পাইথনে 400 Bad Request: KeyError তৈরি হয়। নিরাপদ সমাধানের জন্য request.form.get('name', '') ব্যবহার করা উত্তম — এটি কি না পেলেও এরর না দিয়ে ডিফল্ট মান (যেমন ফাঁকা স্ট্রিং বা None) প্রদান করে।

Jinja2 Templating Deep Dive

জিঞ্জা২ (Jinja2) হলো ফ্লাস্কের বিল্ট-ইন টেমপ্লেট প্রসেসর। এর সাহায্যে এইচটিএমএল পেজের ভেতরে সরাসরি পাইথন ভ্যারিয়েবল প্রিন্ট, কন্ডিশনাল চেকিং (if-else), লুপ (for loop) এবং url_for() দিয়ে ডায়নামিক রিডাইরেক্ট পরিচালনা করা যায়।

Jinja2 এর তিনটি মৌলিক সিনট্যাক্স ডেলিমিটার

{{ variable }} এক্সপ্রেশন বা ভ্যারিয়েবলের মান HTML-এ প্রিন্ট করতে ব্যবহৃত হয় {% statement %} লজিক ও কন্ট্রোল স্টেটমেন্ট (if, else, for loop) চালাতে ব্যবহৃত হয় {# comment #} টেমপ্লেট কমেন্ট লিখতে ব্যবহৃত হয় (ব্রাউজার সোর্সে যায় না)

ডায়নামিক URL রাউটিং ও ভ্যারিয়েবল রুলস

URL-এর ভেতরে ভ্যারিয়েবল অংশ ধরতে <converter:variable_name> সিনট্যাক্স ব্যবহার করা হয়। যেমন <int:score> দিলে ফ্লাস্ক নিশ্চিত করে যে URL-এর ওই অংশটি অবশ্যই পূর্ণসংখ্যা (integer) হতে হবে এবং তা স্বয়ংক্রিয়ভাবে ইনটিজার আকারে ফাংশনের আর্গুমেন্টে চলে আসে।

from flask import Flask, render_template, request, redirect, url_for

app = Flask(__name__)

# ১) ডিকশনারি ও লুপ প্র্যাকটিস করার এন্ডপয়েন্ট
@app.route('/successres/<int:score>')
def successres(score):
    res = "pass" if score >= 50 else "fail"
    exp = {'score': score, 'res': res}
    # ডিকশনারিটি 'results' ভ্যারিয়েবল নামে টেমপ্লেটে পাঠানো হলো
    return render_template("result1.html", results=exp)

# ২) ইফ-কন্ডিশন টেস্ট করার এন্ডপয়েন্ট
@app.route('/successif/<int:score>')
def successif(score):
    return render_template("result.html", results=score)

@app.route('/fail/<int:score>')
def fail(score):
    return render_template("result.html", result=score)

# ৩) মার্কস ক্যালকুলেশন ও ডায়নামিক রিডাইরেকশন
@app.route('/submit', methods=['POST', 'GET'])
def submit():
    if request.method == 'POST':
        # ফর্ম থেকে ৪টি বিষয়ের নম্বর ফ্লোট হিসেবে রূপান্তর
        science = float(request.form['science'])
        maths = float(request.form['maths'])
        c = float(request.form['c'])
        data_science = float(request.form['datascience'])

        # গড় নম্বর হিসাব করা
        total_score = (science + maths + c + data_science) / 4

        # url_for দিয়ে ডায়নামিকভাবে successres রাউটে রিডাইরেক্ট
        return redirect(url_for('successres', score=total_score))
    
    return render_template("getresult.html")

if __name__ == "__main__":
    app.run(debug=True)

Jinja2 কন্ডিশন ও লুপের এইচটিএমএল বাস্তবায়ন

নিচে result.html (if-else কন্ডিশন) এবং result1.html (ডিকশনারি ইটারেশন ও টেবিল লুপ)-এর গঠন দেখানো হলো:

Jinja2 
{# templates/result.html — ইফ-এলস কন্ডিশনের ব্যবহার #}

{% else %}
    <h2 style="color:red;">দুঃখিত! আপনি অনুত্তীর্ণ হয়েছেন। স্কোর: {{ results }}</h2>
{% endif %}

{# templates/result1.html — ডিকশনারির উপর লুপ চালানো #}
<table border="1">
    <tr>
        <th>কি (Key)</th>
        <th>মান (Value)</th>
    </tr>
    {% for key, value in results.items() %}
    <tr>
        <td>{{ key }}</td>
        <td>{{ value }}</td>
    </tr>
    {% endfor %}
</table>
TIP · redirect() ও url_for() কেন সেরা অভ্যাস?

সরাসরি হার্ডকোড করে redirect("/successres/" + str(total_score)) লেখা উচিত নয়। কারণ ভবিষ্যতে রাউটের পাথ পরিবর্তন হলে (যেমন /result/final/<score>) সব জায়গায় কোড বদলাতে হবে। url_for('ফাংশন_নাম', আর্গুমেন্ট...) ব্যবহার করলে ফ্লাস্ক নিজে থেকেই সঠিক URL তৈরি করে নেয়। এর ফলে কোড অনেক বেশি নির্ভরযোগ্য ও মেইনটেইনেবল থাকে।

05

Building a REST API — CRUD Ops

REST (Representational State Transfer) আর্কিটেকচার অনুযায়ী একটি আধুনিক API তৈরি করার পদ্ধতি। এখানে পাইথনের In-Memory ডেটাস্টোর ব্যবহার করে পূর্ণাঙ্গ CRUD (Create, Read, Update, Delete) অপারেশন এবং ক্লায়েন্টের সাথে JSON ফরম্যাটে ডেটা আদান-প্রদান দেখানো হয়েছে।

HTTP মেথড ও CRUD এর সমন্বয়

GET /items সমস্ত আইটেমের তালিকা আনা (Read All) GET /items/<id> নির্দিষ্ট আইডির আইটেম উদ্ধার (Read One) POST /items নতুন আইটেম তৈরি করা (Create, Status: 201) PUT /items/<id> বিদ্যমান আইটেম আপডেট করা (Update) DELETE /items/<id> বিদ্যমান আইটেম মুছে ফেলা (Delete)

পূর্ণাঙ্গ REST API কোড বাস্তবায়ন

নিচের স্ক্রিপ্টটিতে jsonify() দিয়ে পাইথন ডিকশনারিকে JSON রেসপন্সে রূপান্তর করা হয়েছে এবং request.json এর মাধ্যমে ক্লায়েন্টের পাঠানো রিকোয়েস্ট বডি পার্স করা হয়েছে।

In [5] 
from flask import Flask, jsonify, request

app = Flask(__name__)

# প্র্যাকটিস ডেটাস্টোর — মেমোরিতে সংরক্ষিত টু-ডু আইটেম লিস্ট
items = [
    {"id": 1, "name": "Item 1", "description": "This is item 1"},
    {"id": 2, "name": "Item 2", "description": "This is item 2"}
]

@app.route('/')
def home():
    return "Welcome to the sample to do list app"

# ১) GET: সব আইটেম রিটার্ন করার অ্যান্ডপয়েন্ট
@app.route('/items', methods=['GET'])
def get_items():
    return jsonify(items)

# ২) GET: আইডি অনুযায়ী নির্দিষ্ট আইটেম রিটার্ন
@app.route('/items/<int:item_id>', methods=['GET'])
def get_item(item_id):
    # নেক্সট এক্সপ্রেশন দিয়ে নির্দিষ্ট আইডির প্রথম উপাদান খুঁজে বের করা
    item = next((item for item in items if item["id"] == item_id), None)
    if item is None:
        return jsonify({"error": "item not found"}), 404
    return jsonify(item)

# ৩) POST: নতুন আইটেম তৈরি করা
@app.route('/items', methods=['POST'])
def create_item():
    # ইনপুট ভ্যালিডেশন — বডি খালি কিনা বা name কি মিসিং কিনা
    if not request.json or 'name' not in request.json:
        return jsonify({"error": "item not found"}), 400
    
    # অটো-ইনক্রিমেন্ট আইডি তৈরি
    new_item = {
        "id": items[-1]["id"] + 1 if items else 1,
        "name": request.json["name"],
        "description": request.json.get("description", "")
    }
    items.append(new_item)
    return jsonify(new_item), 201

# ৪) PUT: বিদ্যমান আইটেমের তথ্য আপডেট করা
@app.route("/items/<int:item_id>", methods=['PUT'])
def update_item(item_id):
    item = next((item for item in items if item["id"] == item_id), None)
    if item is None:
        return jsonify({"error": "item not found"}), 404
    
    # ফিল্ড আপডেট (রিকোয়েস্টে ভ্যালু না থাকলে আগের মান বজায় থাকবে)
    item['name'] = request.json.get('name', item['name'])
    item['description'] = request.json.get('description', item['description'])
    return jsonify(item)

# ৫) DELETE: তালিকা থেকে আইটেম মুছে ফেলা
@app.route('/items/<int:item_id>', methods=['DELETE'])
def delete_item(item_id):
    global items
    items = [item for item in items if item["id"] != item_id]
    return jsonify(items)

if __name__ == "__main__":
    app.run(debug=True)

বাস্তব টেস্ট ও এপিআই প্রতিক্রিয়া

একটি এপিআই সঠিকভাবে কাজ করছে কিনা তা যাচাই করার জন্য কার্ল (curl) কমান্ড অথবা Postman / Insomnia এর মতো টুল ব্যবহার করা হয়। নিচে টার্মিনাল থেকে ডেটা পাঠানো ও রেসপন্স পাওয়ার নমুনা তুলে ধরা হলো:

cURL 
# ১) নতুন টাস্ক যোগ করতে POST রিকোয়েস্ট:
curl -X POST http://127.0.0.1:5000/items \
     -H "Content-Type: application/json" \
     -d '{"name": "Study Flask", "description": "Complete all 5 practice scripts"}'

# ২) আইডি ৩ এর তথ্য আপডেট করতে PUT রিকোয়েস্ট:
curl -X PUT http://127.0.0.1:5000/items/3 \
     -H "Content-Type: application/json" \
     -d '{"description": "Finished reviewing and documented!"}'
NOTE · jsonify() এর সুবিধা

ফ্লাস্কের jsonify() ফাংশন পাইথন ডিকশনারি বা ডেটা স্ট্রাকচারকে JSON স্ট্রিংয়ে পরিণত করে এবং একই সাথে রেসপন্স হেডার হিসেবে Content-Type: application/json নির্ধারণ করে। ফলে ফ্রন্টএন্ড বা এপিআই কনজিউমার সরাসরি JSON ডেটা হিসেবে এটি হ্যান্ডেল করতে পারে।

TIP · HTTP স্ট্যাটাস কোডের গুরুত্ব

একটি মানসম্মত REST API-তে সঠিক স্ট্যাটাস কোড প্রদান অত্যন্ত জরুরি। নতুন রিসোর্স সফলভাবে তৈরি হলে 201 Created, রিকোয়েস্টে প্রয়োজনীয় ফিল্ড অনুপস্থিত থাকলে 400 Bad Request, আর কাঙ্ক্ষিত আইডি না পাওয়া গেলে 404 Not Found রিটার্ন করা পেশাদার এপিআই ডিজাইনের মূল রীতি।
